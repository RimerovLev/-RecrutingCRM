# Recruit CRM — Roadmap до продаваемого продукта

> Текущая оценка: 7/10 для личного использования, 3/10 для продажи компаниям.
> Цель: довести до 7/10 для продажи.

---

## Приоритет 1 — Без этого продавать нельзя

### 1.1 Multi-tenancy (организации)
**Проблема:** Сейчас данные изолированы по `recruiter_id` — каждый рекрутёр видит только свои данные. Команда из одной компании не может работать вместе над общими кандидатами.

**Что сделать:**
- Добавить таблицу `organizations (id, name, created_at, plan)`
- Добавить `org_id` во все таблицы (profiles, candidates, vacancies и т.д.)
- Переписать RLS политики: изоляция по `org_id` вместо `recruiter_id`
- Admin видит всю свою организацию, не весь глобальный список
- Удалить AdminPage в текущем виде, переделать под org-уровень

**Примерная трудоёмкость:** 2 недели

---

### 1.2 Самостоятельный онбординг компании
**Проблема:** Сейчас новую компанию добавить без SQL-команды невозможно. Ни один клиент не будет ждать ручного вмешательства.

**Что сделать:**
- При регистрации — дополнительный шаг "Название компании"
- Первый юзер компании → автоматически `role = 'admin'` + создаётся `organization`
- Последующие пользователи регаются по инвайт-ссылке (не по открытой регистрации)
- Страница настроек организации в AdminPage

**Примерная трудоёмкость:** 1 неделя

---

### 1.3 Система инвайтов
**Проблема:** Сейчас любой человек может зарегистрироваться. Компании не хотят открытую регистрацию.

**Что сделать:**
- Таблица `invites (token, org_id, email, role, expires_at, used)`
- Admin создаёт инвайт → получает ссылку `https://crm.ru/join?token=xxx`
- По ссылке — форма регистрации, `org_id` подставляется автоматически
- Закрыть обычную регистрацию (или оставить только для создания новой org)

**Примерная трудоёмкость:** 3–4 дня

## Приоритет 2 — Сильно влияет на первое впечатление

### 2.1 Валидация форм
**Проблема:** Можно создать кандидата без имени, интервью в прошлом, вакансию без названия. При демо клиенту это выглядит непрофессионально.

**Что сделать:**
- Обязательные поля: имя кандидата, название вакансии
- Телефон: только цифры, минимум 10 знаков
- Email: валидный формат
- Дата интервью: не в прошлом (предупреждение, не блокировка)
- Дублирование кандидата: предупреждение при совпадении телефона/email

**Примерная трудоёмкость:** 2–3 дня

---

### 2.2 Обработка ошибок сети
**Проблема:** Если Supabase лагит или запрос упал — пользователь видит пустой экран без объяснений. Нет retry-логики, нет понятных сообщений.

**Что сделать:**
- Скелетон-загрузка вместо пустого экрана (мерцающие placeholder-карточки)
- При ошибке сети — кнопка "Повторить" вместо тихого фейла
- Toast-сообщения с конкретной причиной, не просто "Ошибка"
- Timeout на запросы (сейчас запрос может висеть бесконечно)

**Примерная трудоёмкость:** 3–4 дня

---

### 2.3 Кастомный домен + базовый брендинг
**Проблема:** `recruit-crm.vercel.app` выглядит как демо. Клиенты не воспринимают серьёзно.

**Что сделать:**
- Купить домен (например `recruitcrm.ru` или `.io`)
- Подключить к Vercel (15 минут)
- Обновить Supabase URL Configuration
- Логотип вместо текстового "Recruit CRM"

**Примерная трудоёмкость:** 1 день

## Приоритет 3 — Нужно для удержания клиентов

### 3.1 Документация для пользователей
**Проблема:** Нет ни одной страницы объяснения как работать с системой. Каждому клиенту придётся объяснять руками.

**Что сделать:**
- Страница "Быстрый старт" (3–5 шагов: создай вакансию → добавь кандидата → перемести на канбане)
- Всплывающие подсказки (tooltip) на ключевых элементах
- Страница FAQ или база знаний (Notion / GitBook)

**Примерная трудоёмкость:** 2–3 дня

---

### 3.2 Тарифные планы (если SaaS)
**Проблема:** Нет монетизации, нет ограничений по плану.

**Что сделать:**
- Таблица `plans (id, name, max_recruiters, max_candidates, price)`
- Бесплатный план: 1 рекрутёр, 50 кандидатов
- Платный план: неограниченно
- Интеграция с оплатой (ЮКасса для РФ или Stripe для остальных)

**Примерная трудоёмкость:** 1–2 недели

---

### 3.3 Email-уведомления
**Проблема:** Система не присылает никаких уведомлений. О напоминаниях и интервью узнаёшь только зайдя в приложение.

**Что сделать:**
- Supabase Edge Function + Resend (уже настроен send-email)
- Напоминание за 24 часа до интервью → email рекрутёру
- Напоминание в день дедлайна задачи
- Cron через pg_cron или Supabase scheduled functions

**Примерная трудоёмкость:** 3–4 дня
